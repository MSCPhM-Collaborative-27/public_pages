5Quick reference

5.1The contribution loop

  1. Sync main — sync icon in the status bar (§3.3)
  2. Branch: yourusername/topic — must start with your GitHub username, and only one open branch each (§3.2)
  3. Create or edit the file in the right place — table below (§1.3)
  4. Commit — Source Control panel, short message (§3.2)
  5. Push — Sync Changes (§3.2)
  6. Open a pull request on GitHub (§3.2)
  7. Respond to review, then merge — and delete the branch on the PR page to free your slot (§3.2)

For a typo or a small addition, the web editor (§1.2) does the branch and PR steps for you, in the browser. Markdown syntax and how to paste images into a note: §4.2.

elective_courses/PHM50xx/Electives — same layout as the core modules

5.3Terminal commands

Most of this has a VS Code button equivalent — see §3. This table is for the terminal: useful once you're comfortable with it, or when troubleshooting.

CommandWhat it does
git checkout -b yourusername/topicStart a new branch off main
git push -u origin yourusername/topicPush it and link it to GitHub
git pull origin mainPull main's latest changes into your current branch
git statusSee what's changed, and which branch you're on
git add <file>Stage a change
git commitSave the staged changes
git stash / git stash popSet aside uncommitted changes / bring them back
git switch -c yourusername/topicMove uncommitted work off main onto a new branch
git reset --soft HEAD~1Undo the last (unpushed) commit, keep the changes staged
